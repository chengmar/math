# 2013A 冻结解答证据化修订计划

当前冻结版本保持不变。本计划只说明后续授权修订应如何消除审计发现；在视频和来源链未补齐前，案例总体状态维持 `needs_review`。

## P0：先补证据与输入门禁

### 1. 恢复并验证题目视频

对应 finding：AUD-001、AUD-003、AUD-007
当前状态：`needs_review`

修订动作：

- 仅在用户授权的新 solve 修订中，把题目原始视频 1、2 放入允许路径；本 audit 不下载、不跨阶段补取。
- 记录每个视频的路径、字节数、SHA-256、容器、编解码器、帧率、帧数、时长和首尾可解码状态。
- 将预期身份写入不可由求解脚本自行改写的输入清单；运行时逐项比较，而不是只数文件。
- 对至少 10% 的时间段做双遍或双人重叠标注，报告车型/PCU 计数差异和争议处理。

验收标准：

- 输入身份、可解码性与完整性均为 `pass`；
- 任意同名替换、空视频、截断视频或错误帧率测试均为 `fail`；
- 若视频仍不可得，四问闭合和覆盖必须保持 `needs_review`。

### 2. 建立单一来源与检索账本

对应 finding：AUD-008
当前状态：`needs_review`

修订动作：

- 冻结时只生成一个权威来源账本，列出题面输入、允许知识卡、每个卡的副本哈希、检索查询、采用决策和访问时间。
- 由该账本自动派生 `retrieval-log`、使用报告和 FROZEN 元数据，并在冻结前交叉校验。
- 在 FROZEN 中写入实际 seed、运行命令、PowerShell/.NET/System.Drawing 版本和知识卡，而不是空值。
- 对 solve 会话的允许路径访问记录进行一次人工复核。

验收标准：

- 所有检索/知识卡/运行元数据完全一致为 `pass`；
- 禁止源和当前题目的外部答案不存在于访问账本与 payload；
- 在完成独立人工复核前，泄漏 provenance 保持 `needs_review`。

## P1：补齐核心模型与边界

### 3. 实现问题 1 的可运行容量估计器

对应 finding：AUD-003、AUD-009
当前状态：`fail`

修订动作：

- 从带时间戳的标注读取车型数，统一使用一个明确的时长单位。
- 若窗口单位为小时，使用 `sum(PCU)/delta_t_hours`；若为秒，使用 `3600*sum(PCU)/delta_t_seconds`。
- 构造完整信号周期，输出通过率、饱和需求标志、缺帧/遮挡/重复计数标志和容量下界标志。
- 只在满足饱和条件的窗口估计能力；实现并测试三周期中位数、MAD 突变和分段不确定性。
- 把事故形成、稳定占道、撤离与恢复阶段时刻写入可追溯结果，而不是只在论文中描述。

验收标准：

- `60 PCU / 60 s = 3600 pcu/h` 单元测试为 `pass`；
- 未饱和窗口不会被标为容量；
- 人工构造的阶段突变、漏计和不完整周期测试结果符合预期；
- 视频 1 的 `C1(t)` 能由命令行从输入重建。

### 4. 实现信号控制的时变到达与相位敏感性

对应 finding：AUD-002
当前状态：`fail`

修订动作：

- 把 60 s 周期、30 s 相位、黄灯、绿闪及不受控制右转映射成事故方向的 `q(t)`；明确 1500 pcu/h 是周期均值、需求还是事故断面到达率。
- 加入上游路口到队尾的自由流传播延迟和事故发生时的初始信号相位。
- 按事件时刻对 `q(t)`、`C(t)` 分段，使用未舍入的密度与冲击波速度更新 `L(t)`，并在 0 处反射。
- 报告所有可能初始相位或有证据支持的真实相位；把常流 5.306 min 保留为基线，不再作为唯一答案。

验收标准：

- 同均值方波反例能复现约 3.260/3.760 min，证明实现确实读取相位；
- 常流输入退化到 5.306 min；
- 质量守恒、非负队列和事件边界连续性测试均为 `pass`；
- 初始相位未知时输出范围或 `needs_review`，不输出伪唯一值。

### 5. 加入有限路段和溢出后的路口边界

对应 finding：AUD-004
当前状态：`fail`

修订动作：

- 对问题 3 使用原始 240 m，对问题 4 使用 140 m，均作为显式有限链接长度。
- 首次到达边界时停止无限路段公式；预到达结果与后到达结果分文件或分状态。
- 若需要继续模拟，使用上游信号/点队列/CTM 边界处理溢出反馈，并重新定义路口放行与到达率。
- 图表在适用域终点截断或用明显阴影标出 `needs_review` 区域。

验收标准：

- 预到达表中不存在 `L>D`；
- 当前 330 s、145.118692 m 行不再作为有效预到达结果；
- 问题 3 的 10 个超过 240 m 场景被截断、分段或明确标为 `needs_review`。

### 6. 重写问题 2 的因果结论

对应 finding：AUD-005
当前状态：`fail`

修订动作：

- 将 `M=1-p` 限定为描述性换道需求比例，不直接映射为容量排名。
- 用视频识别事故实际占用车道、剩余车道功能、饱和周期、车型组成和排队状态。
- 在匹配信号周期和需求水平后比较归一化容量，并报告不确定性；检查总需求、相位、重车和下游转向约束的混杂。
- 若保留机理模型，显式给出容量损失关于合流比例、可接受间隙和放行头时距的函数，并用独立片段检验。

验收标准：

- 等容量反例不会被错误判成严格排序；
- 视频 1/2 的差异结论有匹配样本、效应量和不确定性；
- 无数据时结论保持 `needs_review`。

## P1：建立真正独立的验证

### 7. 解除解析—数值闭环自证

对应 finding：AUD-006
当前状态：`fail`

修订动作：

- 数值验证从原始 `q,C,v_f,w,k_j` 和通量函数计算，不读取解析函数返回的增长速度。
- 增加第二实现：事件驱动守恒积分或有限体积/CTM；代码路径和公式实现不得共享核心返回值。
- 做至少四个递减步长的收敛表，报告误差阶、质量守恒误差和最坏场景。
- 增加性质测试：`q<=C` 反射、`D=0`、`C->q-`、不可行密度、信号开关、有限边界和恢复消散。
- 视频可用后，把参数标定与评价按时间或片段隔离；不以场景网格代替留出验证。

验收标准：

- 人为扰动解析密度公式时，独立数值实现能使验证为 `fail`；
- 步长收敛与守恒检查为 `pass`；
- 外部有效性只有在独立视频片段上通过后才可为 `pass`。

## P2：数值、论文与复现元数据收尾

### 8. 保留内部全精度并处理奇点

对应 finding：AUD-010
当前状态：`fail`

修订动作：

- 计算对象保存未舍入的速度、时间和密度；只在 CSV/JSON 展示层舍入。
- 对 `|q-C|` 很小的情况输出科学计数法、条件数和“近阈值”警告。
- 明确 `C>=q` 的无增长状态与 `C->q-` 的有限正速度/发散时间，不混用零速度和有限时间。

验收标准：

- `q-C=1e-4` 的长度、速度和时间彼此一致；
- 主区间结果与当前高精度值兼容；
- 极端输入不产生 NaN、错误 pass 或相互矛盾字段。

### 9. 修复论文源并完成 PDF 门禁

对应 finding：AUD-011
当前状态：`needs_review`

修订动作：

- 把两处缺失反斜杠的 `qquad` 改为 `\qquad`。
- 让论文一致性检查解析可见表格/公式中的关键数字，而不只检查隐藏标记。
- 在固定 TeX 环境中连续编译两次，保存引擎版本、命令、stdout、stderr 和 PDF 哈希。
- 人工逐页检查中文字体、公式、表格、图分辨率、交叉引用和页边界。

验收标准：

- TeX 编译退出码 0、无未定义引用；
- 可见数字与机器结果一致；
- PDF 目视检查为 `pass`。
