# 2013A 审计反例与极端测试

总体状态：`needs_review`。下列测试只使用题面、冻结参数和冻结论文自身的公式；它们不是对缺失视频的替代预测。

## CE-01：同均值信号流量不产生同一到达时间

测试目标：检验“用平均 `q=1500 pcu/h` 足以计算问题 4 的唯一时间”。
状态：`fail`

保持冻结中心参数不变：

```text
m = 3
k_j = 140 pcu/(km lane)
v_f = 40 km/h
w = 15 km/h
C = 1000 pcu/h
D = 0.14 km
```

冻结公式为

```text
g(q) = (q-C)/(m k_j-C/w-q/v_f).
```

常流 `q=1500` 给出：

```text
g = 1.583113456 km/h
T = 318.36 s = 5.306 min.
```

构造同一周期均值的可行脉冲：30 s 内 `q=3000`，30 s 内 `q=0`。其周期均值仍为 1500；3000 也小于冻结基本图给出的三车道上游能力 4581.818 pcu/h。按论文声称的“逐状态段重算并在 L=0 反射”规则：

```text
g_green =  7.185628743 km/h
g_red   = -2.830188679 km/h

green-first hit = 195.588 s = 3.259802 min
red-first hit   = 225.588 s = 3.759802 min
```

相对常流结果分别变化 `-38.56%` 与 `-29.14%`。因此相同平均流量不能唯一确定到达时间；至少还需要到达脉冲、相位起点、信号到队尾的传播延迟及右转/转向流的相位映射。这个简化方波不声称是真实视频波形，只证明冻结单点答案对未建模的题面信号条件不具唯一性。

## CE-02：`1-p` 不推出严格车道容量排序

测试目标：检验“换道压力代理 0.56、0.65、0.79 必然推出 through > left > right 的容量排序”。
状态：`fail`

构造满足论文所述“单车道基础饱和流和几何相同”的情景：

- 三个候选剩余车道的基础饱和流均为 `s`；
- 车辆在事故断面上游完成合流；
- 合流完成后，瓶颈放行头时距不随原转向类别变化；
- 下游仍有足够换道距离，不产生回堵。

则

```text
C_through = C_left = C_right = s,
```

尽管

```text
M_through = 0.56,
M_left    = 0.65,
M_right   = 0.79.
```

所以 `M=1-p` 可以描述需要重排的需求比例，但没有容量损失函数、可接受间隙、头时距或下游车道约束时，不能推出严格容量排序。视频匹配周期或额外行为模型是必要证据。

## CE-03：有限路段边界被越过

测试目标：检验生成表是否遵守“首次到达上游路口后模型失效”的边界。
状态：`fail`

原题静态图给出事故点到上游路口 240 m。`<SOURCE_FILE_REDACTED>` 共 45 行，其中 10 行超过 240 m，最大一行为：

```text
q = 1800 pcu/h
C = 600 pcu/h
duration = 10 min
reported L = 597.015 m
```

问题 4 中，`<SOURCE_FILE_REDACTED>` 已在 318.36 s 达到 140 m，却继续输出：

```text
time = 330 s
L = 145.118692 m
```

论文明确说明首次到达后上游信号边界会改变。故这些越界行不能继续标为普通 `growing_queue/pass`；应截断、标为 `needs_review`，或接入溢出后的路口队列模型。

## CE-04：所谓 1 s 数值验证是同式量化

测试目标：检验解析值与数值值是否独立。
状态：`fail`

代码先由解析公式得到 `central.queue_growth_speed_km_h`，随后“数值”循环每秒仍用这个同一速度累加。因此首次越界时间必为

```text
T_dt = ceil(T_exact/dt) * dt.
```

对 `T_exact=318.36 s`：

| 步长 (s) | 首次越界 (s) | 绝对误差 (s) |
|---:|---:|---:|
| 10 | 320.0 | 1.64 |
| 5 | 320.0 | 1.64 |
| 2 | 320.0 | 1.64 |
| 1 | 319.0 | 0.64 |
| 0.5 | 318.5 | 0.14 |
| 0.1 | 318.4 | 0.04 |
| 0.01 | 318.36 | 0.00 |

这只验证循环和舍入，不会发现 `k_a`、`k_b` 或冲击波公式写错。独立验证应从原始参数重新计算通量，或用不同实现的守恒律/有限体积求解器。

## CE-05：窗口时长单位可造成 3600 倍错误

测试目标：检验 `model-selection.md` 的容量公式与 `variables.yaml` 的单位是否一致。
状态：`fail`

假设 60 s 内通过 60 PCU。若 `delta_t` 按变量表定义为小时，则 `delta_t=1/60 h`，正确容量为

```text
C = 60 / (1/60) = 3600 pcu/h.
```

若再按 `model-selection.md` 乘 3600，则得到

```text
C_wrong = 3600 * 60 / (1/60) = 12,960,000 pcu/h.
```

只有在 `delta_t` 明确定义为秒时，`3600*PCU/delta_t` 才正确。冻结文件目前对同一符号采用两种约定。

## CE-06：靠近 `C=q` 时提前舍入破坏内部一致性

测试目标：检验已声明奇点附近的数值稳定性。
状态：`fail`

令 `q=1500`、`C=1499.9999 pcu/h`，其余参数保持中心值。原始双精度结果为：

```text
q-C = 0.0001 pcu/h
g_raw = 3.539822925e-7 km/h
T_raw = 23,730,000.56 min
```

`Get-KinematicResult` 在返回前把速度舍入到六位小数，得到 `g_reported=0`；`Get-QueueLengthM` 再使用这个已舍入值，任何有限时长的长度都变成 0，而同一对象仍报告有限的巨大到达时间。主情景区间 800-1200 pcu/h 不受此极端问题影响，但实现没有稳定处理其论文主动强调的 `C -> q-` 边界。

## CE-07：输入“身份”可被同名替换绕过

测试目标：检验 `V01_source_identity` 是否真的核验身份。
状态：`fail`

代码会计算输入哈希并写入报告，但 `V01_source_identity` 的判定条件只有 `sourceFiles.Count -eq 2`；没有任何预期 SHA-256 比较。因此两个路径相同、内容不同的文件仍会得到 `pass`。类似地，任意两个扩展名为 `.mp4/.avi/...` 的空或损坏文件会使 `input_completeness_status` 变为 `pass`，因为没有解码、时长或帧数检查。

本次审计先于运行独立验证了两个真实输入和全部 FROZEN 哈希，所以实际隔离复现没有被该缺陷污染；反例针对的是冻结代码所宣称的身份门禁。
