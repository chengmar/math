# 2014A 审计反例与极端测试

以下测试均在 audit 根目录的副本或独立脚本中执行，未修改 `frozen-solution`。

## CE-01：验证器可对百万米误差和伪 PDF 给出 pass

状态：**fail**。

在 `audit-verifier-counterexample` 中执行两项只针对审计副本的改动：

1. 用 28 字节的 `code/requirements.txt` 内容充当 `paper/<SOURCE_FILE_REDACTED>`；它不是 PDF。
2. 把 `results/<SOURCE_FILE_REDACTED>` 的主减速误差改为：位置 `1,000,000 m`、速度 `10,000 m/s`、质量 `1,000 kg`，但保留该行自报的 `status=pass`；随后只更新同目录、可自行修改的 `results/manifest.json` 条目哈希。

运行：

```powershell
python -B code\verify.py
```

实际结果：

```json
{
  "exit_code": 0,
  "overall_status": "pass",
  "manifest_hashes": "pass",
  "independent_reintegration": {
    "status": "pass",
    "max_position_error_m": 1000000.0,
    "max_velocity_error_mps": 10000.0
  },
  "paper_compile": {
    "status": "pass",
    "reason": "compiled PDF found"
  }
}
```

成因可直接定位到 `verify.py`：152--158 行信任 CSV 的 `status`，不重新应用误差阈值；205--209 行只检查 PDF 是否非空。这个反例不说明冻结数值本身有百万米误差，而是证明内置验证器不能作为独立正确性证据。

## CE-03：DEM 垂直基准使“4 m 自由落体”发生变化

状态：**needs_review**（配准条件需人工确认），代码未耦合高程的事实为 **fail**。

精 DEM 中：

- 图中心高程：`14.900000572 m`；
- 冻结选点高程：`8.100000381 m`；
- 选点相对中心：`-6.800000191 m`。

代码从精图中心上方 100 m 开始横移，却把末端绝对垂直坐标直接写成 30 m 和 4 m，没有加入这 `-6.8 m` 地形差。若把精图中心地面作为 100 m 悬停的垂直基准，则代码关机点对所选低地的实际净空为

\[
4+(14.9-8.1)=10.8\ \mathrm m,
\]

而不是 4 m。用代码同一局部重力计算：

| 量 | 冻结计算 | 条件化地形基准 |
|---|---:|---:|
| 自由落体高度/m | 4.0 | 10.8 |
| 下落时间/s | 2.215 | 3.640 |
| 撞击速度/(m/s) | 3.611 | 5.934 |

`audit_terrain_coupling.py` 还把粗图中心→粗选点的 `+1.0 m` 和精图中心→精选点的 `-6.8 m` 串联到同一绝对高度。保持原时序时，推力仍在题定 `1500--7500 N` 内，但最小值降至约 `1500.825 N`，原 5% 裕度 fail。现有 `h>=0` 又会把所选低地上的正常 4 m 净空误判为负绝对高度，说明代码需要把“绝对高度”和“地形净空”拆成两个量。

更一般的简化反例是：如果同一平面坐标中所选点比基准高 5 m，代码的 `h=4 m` 仍会判边界 pass，但探测器在到达该端点前已经与地形相交。

## CE-04：位置速度连续不代表控制连续

状态：**fail**。

`audit_numeric_checks.py` 以不大于 0.02 s 的网格重建冻结参考。段间位置、速度、质量跳变都在浮点误差范围内，但推力命令为：

| 边界 | 推力大小跳变/N | 推力方向跳变/° |
|---|---:|---:|
| 主减速→快速调整 | -153.083 | 26.288 |
| 快速调整→粗避障 | -27.782 | 179.938 |
| 粗避障→精避障 | -3355.790 | 11.998 |
| 精避障→缓速下降 | -50.227 | 11.678 |

其中近 180° 的翻转要求瞬时完成姿态反向，任何有限姿态角速度模型都会使该命令不可执行。论文把姿态速率和节流速率列为局限，但仍把名义控制约束标为 pass，二者不相容。

## CE-05：同一“半径”对应的圆盘和方窗不是同一足迹

状态：**fail**（定义一致性），本数据硬安全状态仍为 **pass**。

代码对 5 m、0.1 m/像素的足迹使用 101×101 方窗，共 10,201 像素；同半径圆盘只有 7,845 像素，方窗面积多约 30.03%，角点距中心约 7.071 m。

简化地形反例：在半径 5 像素方窗的右下角放一个高度 10 的障碍，其他位置为 0。该角点距中心 `sqrt(2)*5=7.071` 像素：

- 方窗最大值：10；
- 半径 5 圆盘最大值：0。

所以文字中的“半径足迹”和代码方窗可对同一地形给出不同评价。本例真实精 DEM 上，圆盘重算把选点由 `(row=330,col=572)` 移到 `(330,569)`，即向西 0.3 m；两者硬阈值都 pass。

## CE-06：内部优化目标的离散漏检

状态：**fail**（仅内部目标），题定和设计约束为 **pass**。
