# 证据化修订计划

本计划只提出后续修订建议；本次 audit 未修改 `frozen-solution`。

## P0：恢复可信冻结基线

状态：`fail`

1. 由冻结打包流程在当前 audit 工作区之外重新建立最小冻结包，不在本会话中修改现有冻结副本。
2. 生成全量清单，每项至少包含规范化相对路径、字节数和 SHA-256。
3. 将所有能影响复现或论文结论的文件纳入清单，至少包括源代码、依赖声明、运行脚本、转换后输入、结果、图、论文源码、编译 PDF、复现说明和验证脚本。
4. 若排除缓存或临时构建文件，清单必须显式记录排除规则，并证明这些文件不参与任何计算、验证或论文编译。
5. 把清单自身的 SHA-256 写入不可与冻结包一起任意改写的 audit `phase-lock.json` 或等价可信锚点；仅在冻结树内放置自描述清单不足以建立信任。

验收标准：全量清单存在且可信锚定，逐文件检查为 `pass`，没有未解释的新增、缺失或哈希不一致文件。

## P0：重新启动独立 audit

状态：`needs_review`

冻结打包修复后开启新的 audit 会话，从阶段锁和 FROZEN 清单重新开始；不要跨阶段恢复本会话，也不要把当前未执行项目记作已复现。

验收标准：新会话预检为 `pass` 后才创建干净复现环境。

## P1：干净环境复现

状态：`needs_review`

1. 将已验证冻结包复制到新的临时目录，记录复制前后的全量哈希。
2. 建立隔离 Python 环境，离线安装锁定依赖；记录 OS、Python、PowerShell、Office/转换依赖和精确版本。
3. 按 `reproducibility.yaml` 运行转换、求解、独立验证、二次哈希比较和论文编译。
4. 保存每条命令、工作目录、stdout、stderr、退出码、耗时以及产生文件的哈希。
5. 将复现产物与冻结预期逐项比较，不以“脚本退出码为 0”替代数值或文件一致性。

验收标准：命令执行与产物比较均为 `pass`；任何环境依赖差异明确标为 `needs_review` 或 `fail`。

## P1：数学与数据审查

状态：`needs_review`

在复现通过后，逐项核查：小问覆盖；公式推导和单位量纲；资源、整数、上下界及业务约束；初值和边界；可辨识性、可行性、有界性和收敛；预测时间切分与泄漏；验证集混用；过拟合；异常敏感性；随机与数值稳定性；论文—代码—图表逐值一致性。

验收标准：每个判断均定位到文件、公式、数据行或运行日志；无法自动确定者为 `needs_review`，不得伪造数学正确性。

## P2：反例与简化基线

状态：`needs_review`

在干净副本中运行零需求、极端需求、单类支配、约束冲突、尺度变换、异常值和多随机种子测试；同时建立朴素趋势/比例分配等更简单基线，与复杂模型在同一严格时间切分上比较。

验收标准：反例输入、预期性质、实际输出和判定均可复现；基线比较不复用验证期信息。
